# v5 数据库写入保护

旧版应用并非都检查 SQLite 的 user_version，因此单独标记 v5 不能阻止旧版本写入。

当前 main 在连接中注册 `comfyui_light_writer_version()`，并为 batches、jobs、job_attempts、kv 安装持久化触发器。INSERT、UPDATE、DELETE 必须通过该连接能力检查；没有注册函数的旧版连接在执行写入时失败，仍可以只读查询。升级旧库和重新打开已经是 v5 的库都会安装保护，user_version 保持 5。

所有正常写入应经 `openDb` 创建连接。此前已支持 v5、但尚未注册该函数的版本也会被拒绝写入。该机制阻止旧应用的正常写入路径，不是对可任意删改数据库 schema 的管理员进行访问控制。

升级须先使用 SQLite 备份接口生成一致性备份，避免遗漏 WAL 中的数据。验证完整性、外键、原有数据保留和远端终态后，再按用户授权删除旧备份。回退到旧程序必须使用升级前备份及独立 DATA_DIR，不能移除保护后继续写入 v5 数据库。
